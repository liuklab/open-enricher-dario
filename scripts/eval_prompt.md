## Inference setup

Metadata is generated by `{model_id}` (`{dtype}`, device `{device_map}`, attention `{attn_implementation}`). This is a 2B vision-language model. It receives sampled video frames plus the text prompt in `src/open_enricher/metadata_prompt.md`. It does not receive the audio track, so dialogue and sound are invisible unless they appear as readable on-screen text.

The configured source is about 50 minutes (`{video_name}`). Frame selection and pixel budget are fixed in `src/open_enricher/config.py` and applied before `generate()`. You cannot change them. The sidecar of the run records the values actually used.

Fixed video input:

- `video_seconds` is `{video_seconds}`. `None` sends the whole file. A positive integer sends only the first that many seconds: ffmpeg re-encodes that prefix without audio, and the processor samples the clip. If the file is already shorter, the original file is used. You cannot change this value.
- `fps` from `metadata_params.json` is the requested sampling rate. The processor then keeps `n = clamp(duration_seconds * fps, {min_frames}, {max_frames})` frames, spaced uniformly from the first frame of that input to the last. `duration_seconds` is the clip length when `video_seconds` is set, otherwise the full file. The cap only changes how far apart the frames are.
- When `video_seconds` is None, the input is the full episode (about 50 minutes). Then `duration_seconds * fps` exceeds `{max_frames}` for any `fps` above about 0.26. Raising `fps` inside the allowed range does not add frames. Lowering `fps` below that threshold does drop frames and makes coverage worse.
- When `video_seconds` is a positive integer, `duration_seconds` is that many seconds (or the real file length if shorter). If `duration_seconds * fps` stays under `{max_frames}`, raising `fps` adds frames inside the clip. The rest of the episode is invisible.
- `min_frames` is `{min_frames}`. It only matters for clips of a few seconds.
- `max_frames` is `{max_frames}`. The 2048-frame long-video cap does not fit in the 22GB GPU: the vision encoder runs out of memory before `generate()` writes any text.
- `max_video_tokens` is `{max_video_tokens}` per frame. With this budget the per-frame floor binds first, so frames stay at the minimum resolution.
- `video_shortest_edge` is `{video_shortest_edge}` and `video_longest_edge` is `{video_longest_edge}`. `longest_edge` is the T×H×W pixel budget, about `{visual_token_budget}` visual tokens after the temporal compression of 2. `cap_pixels_per_frame` is always true, so that budget is split across the sampled frames.
- Each sampled frame is small. Fine detail (faces, credits, burned-in subtitles) is often unreadable. Pairs of frames are encoded together (`temporal_patch_size` 2), and those two frames are seconds apart, not continuous motion.

`generate()` then writes the reply using only the seven keys in `src/open_enricher/metadata_params.json`: `fps`, `max_new_tokens`, `do_sample`, `temperature`, `top_p`, `top_k`, `repetition_penalty`. `temperature`, `top_p`, and `top_k` are used only when `do_sample` is true.

## Why the metadata text is often bad

Judge the `.txt` as the raw model continuation. A bad file is usually one of these, and they have different causes:

- Broken generation, not a thin video. The model starts a JSON object, then leaves the schema: comments, extra keys, prose about "correcting the format~~", then a long chain of loosely related words until~~ `max_new_tokens` ~~cuts it off mid-token.~~ `repetition_penalty` ~~above about 1.1 pushes already-used tokens (braces, quotes, ordinary words) out of the distribution, so the 2B model fills the rest of the budget with new words instead of closing the JSON. A high penalty does not fix repetition.~~ `do_sample: true` ~~with a non-trivial temperature makes that drift more likely. Greedy decoding (~~`do_sample: false`~~) is the stable choice for one strict JSON object; the file must still contain a~~ `temperature` ~~greater than 0 because the loader~~ rejects 0.
- Truncated JSON. The object is valid up to the end of the file and stops mid-string or mid-array. `max_new_tokens` was too small for the schema, or the model had already derailed and spent the budget on the word list. A larger budget does not repair a derailed reply; it makes the word list longer.
- Ungrounded story. The JSON is well formed but describes events, names, or dialogue the samples cannot support. The model sees sparse silent frames. Treat invented plot as low quality even when the title happens to match the episode. Do not try to fix that by raising `fps` while the `{max_frames}` cap is binding.
